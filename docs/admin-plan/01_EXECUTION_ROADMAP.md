## 단계 0 — 범위와 결정을 고정한다

### 고정할 항목

- 단일 매장으로 시작하되 모든 업무 테이블에 `store_id` 사용
- 통화 KRW, 시간대 Asia/Seoul
- 상품 옵션 조합 하나가 SKU 하나
- 금액은 원 단위 정수
- 품절과 재고부족은 SKU 재고에서 파생
- 삭제 대신 보관/soft delete
- 관리자 역할: OWNER, ADMIN, PRODUCT_MANAGER, VIEWER
- 상품 시리즈는 여러 상세페이지를 묶는 기능
- 소재·색상·게이지·길이는 옵션/SKU
- 정기구독, 리뷰이동, 외부 마켓 승인상태는 1차 제외

### 게이트

- `docs/adr/`에 결정 문서가 존재한다.
- POS 저장소와 웹 저장소가 물리적으로 분리된다.
- 1차 범위 밖 기능이 사이드바에 노출되지 않는다.

## 단계 2 — 인증, 매장, 역할, RLS

### 구현

- Supabase Auth
- `stores`, `profiles`, `store_members`
- OWNER/ADMIN/PRODUCT_MANAGER/VIEWER
- 서버 세션 검사
- `/admin/**` 보호
- 매장 선택 컨텍스트
- 역할별 서버 권한 검사
- RLS와 Storage 경로 격리의 기반
- 두 매장 seed와 교차 접근 테스트

### 게이트

- 로그인하지 않은 접근은 차단된다.
- 비활성 멤버는 접근할 수 없다.
- A 매장 사용자가 B 매장 데이터를 읽거나 수정하지 못한다.
- VIEWER의 write 요청은 UI뿐 아니라 서버와 DB에서도 거절된다.

## 단계 3 — 관리자 공통 셸

### 구현

- 상단 바, 좌측 사이드바, 페이지 헤더
- 패널, 탭, 검색패널, 상태요약, 데이터툴바, 테이블 골격
- 로딩, 최초 빈 상태, 검색결과 없음, 오류, 권한 없음
- 확인 모달, 토스트, 하단 고정 작업바

- 1280px 미만 사이드바 축소

- 1440px 기준으로 제공 화면과 유사한 정보 밀도를 갖되 독자 브랜드다.
- 1280px와 1024px에서 주요 조작이 가려지지 않는다.
- 키보드 포커스와 label이 존재한다.
- 미구현 메뉴나 무반응 버튼이 없다.

## 단계 4 — 상품 도메인 DB

### 구현 순서

1. 확장과 enum
2. 카테고리·배송 프로필
3. 상품
4. 옵션·옵션값
5. SKU
6. 재고 수준·재고 이동
7. 미디어
8. 상태 이력·감사로그
9. 관계·시리즈·템플릿·공지
10. import job

### 핵심 제약

- `store_id + sku` 고유
- `store_id + slug` 고유
- 예약재고는 보유재고보다 클 수 없음
- 가용재고 = 보유재고 - 예약재고
- 게시된 상품의 SKU는 hard delete하지 않음
- 감사로그는 수정·삭제 불가
- 낙관적 잠금 `version`

### 게이트

- 빈 DB에서 migration 전체 적용 성공
- DB reset 후 재적용 성공
- seed가 반복 가능
- 제약조건 테스트 통과
- 주요 목록 쿼리 실행계획 확인

## 단계 5 — 상품 선행 기준정보

### 구현

#### 카테고리

- 최대 4단계
- 검색, 추가, 수정, 정렬, 활성/비활성
- 연결 상품 수
- 사용 중 삭제 차단

#### 배송정보

- 무료/정액/조건부 무료
- 제주·도서 추가비
- 출고 소요일
- 반품비·교환비
- 출고지·반품지
- 사용 중 삭제 차단, 비활성화 제공

#### 미디어 업로드 기반

- private bucket
- 매장별 object path
- signed upload
- MIME, 용량, 해상도 검증
- 업로드 상태 READY/FAILED
- 썸네일 경로 계약

### 게이트

- 상품 폼이 참조할 활성 카테고리와 배송정보가 존재한다.
- 다른 매장 파일 경로 접근이 차단된다.
- 참조 중인 기준정보 삭제가 거절된다.

## 단계 6 — 읽기 전용 상품목록

### 먼저 읽기만 만드는 이유

입력 폼보다 목록 쿼리와 상태 정의를 먼저 검증해야 `대시보드`, `일괄 처리`, `CSV`, `고객몰`이 같은 기준을 공유한다.

### 구현

- `/admin/products`
- URL 쿼리 기반 필터
- 상태 count
- 상품명/코드/SKU/브랜드/카테고리 검색
- 판매·전시·재고 상태
- 기간 필터
- 서버 페이지네이션·정렬
- 열 표시 설정
- 고정 선택/상품명 열
- 가로 스크롤
- seed 10,000건 성능 검증
- 이 단계에서는 수정·일괄 버튼을 노출하지 않음

### 게이트

- 새로고침과 뒤로가기 후 필터 유지
- `count`와 같은 필터의 `total` 일치
- 품절·재고부족 계산이 DB/서버에서 일관됨
- 검색결과 없음과 최초 데이터 없음이 구분됨

## 단계 7 — 상품 임시저장 폼

### 이번 단계에서 구현할 섹션

- 카테고리
- 상품명·상품코드·브랜드·제조사·원산지
- 판매가·비교가격·과세
- 판매기간·예약판매
- 최소/최대 구매수량
- 배송정보
- 슬러그
- 전시상태
- 단일 기본 SKU
- 명시적 `임시저장`

복잡한 옵션, 이미지, 에디터, 법정고시는 다음 단계에서 추가한다. 구현되지 않은 섹션은 화면에 빈 아코디언으로 만들지 않는다.

### 게이트

- 작성→임시저장→목록→재진입 데이터 일치
- 불완전한 초안 저장 가능
- 다른 관리자가 먼저 수정한 경우 409 충돌
- 이탈 경고
- 서버가 모든 입력을 재검증

## 단계 8 — 옵션, SKU, 재고

### 구현

- 옵션 그룹 최대 5개
- 옵션값 추가·삭제·정렬
- Cartesian product 조합 생성
- 안정적인 `combination_key`
- 조합별 SKU·바코드·가격·활성 여부
- 보유재고·예약재고·안전재고
- 재고 조정 사유
- 재고 이동 이력
- 기존 SKU 보존과 비활성화
- 대량 셀 편집

### 게이트

- `색상 2 × 게이지 3 = SKU 6개`
- 옵션 순서 변경만으로 기존 SKU가 새 SKU로 바뀌지 않음
- SKU/바코드 중복 차단
- 재고조정은 이력 없이 직접 덮어쓰지 않음
- 가용재고 파생값 테스트

## 단계 9 — 이미지, 상세설명, 고시, 게시

### 구현

- 대표 이미지 1장
- 추가 이미지 최대 20장
- 옵션 이미지 매핑
- 정렬과 대체텍스트
- 상세설명 편집기 어댑터
- 서버 HTML 정화
- 카테고리별 고시정보 동적 폼
- SEO 제목·설명·검색어
- 미리보기
- 게시 검증
- 판매 시작/일시중지/종료
- 오류 요약→해당 섹션 이동
- 하단 고정 작업바

### 게시 차단

- 카테고리 없음
- 상품명/슬러그 없음 또는 중복
- 판매가 1원 미만
- 활성 SKU 없음
- 중복 SKU/옵션 조합
- 배송정보 없음
- 대표 이미지 미완료
- 상세설명 없음
- 고시정보 누락
- 날짜·할인 계산 오류

### 게이트

- 불완전 초안은 저장되지만 게시되지 않음
- 게시 성공 시 고객몰 조회용 상태가 원자적으로 전환됨
- 이미지 업로드 중 게시 차단
- HTML 정화 보안 테스트
- 수정 충돌 처리

- 행별 수정 진입

## 단계 12 — 연관상품과 상품 시리즈

### 연관상품

- 비슷한 상품
- 함께 구매
- 상위 상품
- 액세서리
- 자기참조·중복 차단
- 정렬

### 상품 시리즈

- 별도 상세페이지 상품을 하나의 시리즈로 묶음
- 대표상품
- 시리즈 내 정렬
- 고객몰 전환용 데이터 계약

### 금지

소재·색상·게이지를 상품 시리즈로 만들지 않는다. 해당 값은 옵션/SKU다.

### 게이트

- 자기 자신 연결 불가
- 같은 관계 중복 불가
- 대표상품은 시리즈 소속 상품이어야 함
- 다른 매장 상품 연결 불가

## 단계 13 — 실제 데이터 대시보드

### 이 시점에 만드는 이유

상품과 목록 필터가 완성된 뒤 같은 query builder를 재사용해야 숫자가 신뢰 가능하다.

### 카드

- 전체
- 임시저장
- 판매중
- 품절
- 재고부족
- 판매중지
- 전시중지
- 정보 누락

### 규칙

- 카드 클릭→필터된 상품 목록
- 카드 count와 목록 total 동일
- 오류를 0으로 위장하지 않음
- 마지막 갱신 시각
- 미구현 주문·문의 카드 숨김

### 게이트

모든 카드에 대해 `dashboard count == destination list total` 통합 테스트가 통과한다.

## 단계 14 — CSV 일괄등록

### 흐름

```text
양식 다운로드
→ 파일 업로드
→ staging
→ 행/열 검증
→ 미리보기
→ commit
→ 결과 CSV
```

### 규칙

- UTF-8
- 최대 500행
- 신규/수정 모드 분리
- 업로드 즉시 운영 테이블 반영 금지
- job idempotency
- 오류 행과 열 명시
- 외부 이미지 URL은 기본 비활성
- CSV 수식 인젝션 차단

### 게이트

- 정상/오류 혼합 파일 부분 성공
- 같은 job 재실행 중복 방지
- 실패 결과 다운로드
- 500행 성능 기록
