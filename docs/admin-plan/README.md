# 피어싱 자사몰 관리자 — 단계별 구현 계획 v3

이 패키지는 제공된 스마트스토어센터 홈·상품관리 화면을 참고해, **피어싱 자사몰 관리자**를 실제 코드로 나눠 구현하기 위한 실행 문서다.

## 프로젝트 경계

- 새 웹 저장소에서 구현한다.
- 기존 태블릿 POS·Capacitor·APK 저장소는 수정하지 않는다.
- 고객용 자사몰과 관리자는 같은 상품 DB를 사용한다.
- 현재 패키지의 구현 범위는 `관리자 인증 + 상품관리 + 상품 대시보드`다.
- 주문·결제·배송·클레임은 고객몰 주문 흐름이 만들어진 뒤 후속 구현한다.
- 네이버 로고, 스마트스토어 명칭, 고유 아이콘, 문구, 고유 배치를 복제하지 않는다.

## 이전 순서에서 수정한 점

대시보드를 초기에 만드는 순서는 폐기한다. 상품 데이터와 목록 쿼리가 완성되기 전에 대시보드를 만들면 가짜 숫자, 중복 집계 로직, mock 데이터가 남는다.

새 순서는 다음과 같다.

```text
데이터 기반
→ 조회 화면
→ 입력 화면
→ 운영 기능
→ 보조 기능
→ 실제 집계 대시보드
→ 대량 등록
→ 운영 강화
```

## 사용 순서

1. `01_EXECUTION_ROADMAP.md`를 읽는다.
2. `02_CODEX_RUNBOOK.md`의 작업 규칙을 저장소에 적용한다.
3. `03_PROGRESS_CHECKLIST.md`를 프로젝트 진행표로 사용한다.
4. `spec/` 문서를 기준 명세로 둔다.
5. `stages/STAGE_00_...`부터 한 파일씩 Codex에 전달한다.
6. 현재 단계의 완료 게이트가 전부 통과하기 전에는 다음 단계로 넘어가지 않는다.
7. 각 단계 종료 후 `templates/STAGE_RESULT_TEMPLATE.md` 형식으로 결과를 기록한다.

## 예상 규모

단일 숙련 풀스택 개발자와 Codex를 기준으로 관리자 상품관리 MVP는 대략 **32~47 개발일** 규모다. 디자인 수정, PG 연동, 주문관리, 고객몰까지 포함한 기간이 아니다. 긴 상품등록 화면과 옵션/SKU/이미지/권한/RLS를 포함하면 1~2주짜리 작업으로 보는 것은 비현실적이다.
